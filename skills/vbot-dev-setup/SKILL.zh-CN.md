# VBOT 开发环境

<p align="center"><a href="SKILL.md">English</a> | 中文</p>

## 定位工作区

先解析本 Skill 的实际目录：其所在的 `skills/vbot-dev-setup/` 属于 VBOT Lab 仓库，
即使它通过其他项目中的软链接被发现也一样。
该仓库还必须包含 `tools/check_environment.py` 和 `catalog/capabilities.json`。
如果只复制了本 Skill，请用户提供完整仓库路径；不要执行用户应用目录中的同名工具，
也不要自动下载依赖。

## 选择本次目标

- 仅咨询或清点：只解释或执行所要求的检查；不能因为调用了本 Skill 就安装软件、部署或联系设备。
- 仅配置设备 shell：按下方设备章节操作，完成所要求的配置后停止。
- 完整开发搭建／跑通首个示例：按下方完整流程执行。工具清点只是第一个检查点，不是完成条件。

从已有上下文确定开发语言、当前构建环境和目标设备／地址。沿用已有语言选择；
未指定时建议默认 Python 并说明选择。设备操作前确认缺失的设备信息；本地准备可独立推进。
不要默认同时执行两条语言路径。

区分工作站、开发容器和设备 shell。设备侧请求先确认目标设备／类型与软件版本，再按下方设备章节操作。
不要在机器人上执行工作站清点，也不要向工作站 shell 加载设备路径。

## 工作站清点与解读

确认用户检查的是工作站（`host`）还是现有开发容器（`container`）。
不明确时说明上下文或询问；容器内不要求 Docker。
在解析后的 VBOT Lab 根目录运行下列命令，或使用对应绝对路径：

```bash
python3 tools/check_environment.py --profile host
```

容器检查将 `host` 替换为 `container`。仅在用户设备类型已知时添加 `--robot-type`，
不能从共用硬件推断类型。命令返回 JSON，包含工具存在情况、发布范围、SDK 接入状态和未执行的检查。

- 退出码 0：本次本地清点完成，未发现必需工具缺失或设备类型发布阻塞；不代表 SDK 或设备已就绪。
- 退出码 1：缺少必需工具，或所选设备属于后续发布类型。
- 退出码 2：参数无效、设备类型未知，或工作区／能力索引数据无效。
- 命令存在不代表已验证版本、Docker daemon 权限、镜像可用性或设备连接；检查器不执行发现的工具。
- 独立于退出码报告 SDK 接入阻塞，不编造安装命令、导入名称、topic 或 Bazel 应用目标。

需要搭建环境时，仅阅读相关[环境指南](../../docs/getting-started/README.zh-CN.md)
和[容器指南](../../docker/README.zh-CN.md)。安装软件、启动或拉取容器是单独操作，
须符合用户请求。选择接口时读取[能力索引](../../catalog/README.zh-CN.md)及其链接的来源文档。

## 从 host 进入开发容器

在 host 上检查环境或完整搭建时，按[容器指南](../../docker/README.zh-CN.md)检查 Docker：
CLI 与服务端访问、Compose v2、当前 Docker context 及 Compose 配置。命令设置合理超时。
清点脚本保持离线，其成功不能代替这些检查。仅咨询时解释命令，不实际执行。
Docker 未安装、daemon 不可用或权限不足时，说明具体处理方式，在进入容器前停止。
不要自动修改 socket 权限、用户组、Docker context 或安装软件。

ARM64 应用的后续开发、SDK 准备、Bazel 构建、离线预览与打包均在提供的开发容器中进行，
不在 host 或机器人上进行。host 负责 Docker、挂载仓库，以及需要时通过 SSH 传输制品；
不要求 host 安装 Bazel 或 SDK。完整搭建时，**先查找已有开发容器，再决定是否拉取镜像或创建容器**：

- 优先使用用户指定的容器；否则按容器指南列出全部容器（包括已停止的），检查候选的镜像身份、
  工作区挂载和状态，也考虑不属于当前仓库 Compose 项目的容器。
- 合适的容器已运行：直接 docker exec，不拉取、重建或重启。
- 合适的容器已停止：启动同一个容器，再 exec 进入。
- 多个候选都匹配时请用户选择；不能仅凭名称判断。镜像或工作区挂载不匹配时说明差异，不替换已有容器。
- 仅在不存在合适容器时按指南创建。不为搭建删除容器、清空缓存或强制重建；镜像升级是单独操作。

记录选定的容器 ID 和容器内工作区路径，后续命令沿用。
仅检查时给出后续步骤，不拉取或启动容器；搭建流程不额外执行匿名访问探测。

进入容器后从 `/workspace` 继续，使用 container 清点模式。
Agent 若运行在 host，后续开发命令必须通过选定容器执行；在另一个终端打开交互 shell
不代表 Agent 的执行环境已切换。先确认挂载仓库、镜像和容器身份。
已经位于所提供容器内时跳过 host Docker 检查，不要求容器内安装 Docker 或挂载 host Docker socket。

生成 ARM64 原生产物前检查容器架构及实际编译目标。使用 Docker 不会自动把 x86_64 构建变成 ARM64。
按 SDK 支持的构建路径操作；所提供容器不能生成兼容 ARM64 二进制时，报告阻塞并请求匹配的容器环境。
不要回退为 host／设备编译，不臆造交叉工具链，也不修改 host 仿真配置。

## 完整搭建：构建、部署、收到状态

仅阅读所选语言的参考文档。复用已验证的配置，不因再次执行流程就重复安装或创建部署。

1. **准备构建环境。** 执行对应的环境清点。完整搭建还需实际检查相关工具版本并完成构建，
   命令存在不代表可用。按上文完成 host 到容器的切换，在提供的容器中执行开发步骤。
   镜像不可用时说明错误；可复用由该镜像启动的现有容器，不回退到 host 工具链。
   打包的 Bazel 依赖按[离线构建指南](../../docs/development/offline-build.zh-CN.md)使用。
   缺少制品时使用文档列出的公开发布来源或请求提供依赖包，不替换成未记录的依赖仓库。
2. **准备 SDK 并构建只读示例。** 使用订阅 `/locomotion/status` 的
   [subscribe-state](../../recipes/subscribe-state/README.zh-CN.md)。
   - Python：按 [SDK 指南](../../packages/aorta/python/README.zh-CN.md)选择配套版本并实际检查导入。
     在开发容器中构建 `//recipes/subscribe-state:main` 并执行离线预览；按
     [Python 部署流程](../../docs/development/python-deployment.zh-CN.md)准备匹配设备的 wheel。
   - C++：按 [C++ SDK 指南](../../packages/aorta/cpp/README.zh-CN.md)设置配套 SDK／Schema 路径，
     构建 `//recipes/subscribe-state:main_cpp`。设备程序必须是 ARM64 且运行库兼容。
     x86_64 预览产物不能作为 ARM64 部署产物；选择 ARM64 SDK 压缩包不等于配置交叉编译。
     没有支持的 ARM64 构建环境时报告该阻塞，不改为在机器人上构建。
3. **连接与配置。** 按下方设备章节先验证 `vbot` SSH 公钥登录，再配置设备 shell。
   核对设备架构与相关运行时版本是否匹配制品。使用独立的原生 Aorta SDK shell，
   本示例不要求加载 ROS。Python 按部署指南隔离 `PYTHONPATH`，不能假定激活 venv 会移除 ROS 包路径。
4. **只部署所选示例。** 完整搭建包含将文档规定的应用包传到新的用户应用目录并准备运行时。
   写入前确认目标设备；请求排除设备写入时，停在本地制品准备并说明后续步骤。
   使用所选语言的部署指南：
   - Python：传输源码和 ARM64 wheel，在设备创建 venv、离线安装并检查导入。
     不传输工作站 venv，也不假定设备上已有仓库。
   - C++：传输可执行文件与所需动态库，检查架构、校验和及动态库解析，再直接运行
     `./bin/subscribe-state`。设备无需 Bazel 或编译器，不替换系统库。
5. **实际收到状态。** 从记录的应用目录、在配置好的运行环境中，执行所选语言示例的
   `--execute --count 3 --timeout 10` 有时限命令。需收到解码后的状态消息且进程成功退出；
   离线预览、topic 列表或清点退出码不算在线成功。超时或失败时检查相关环境、导入、动态库或路由错误，
   说明失败阶段。不无限重试，也不修改服务、权限、bridge 配置或机器人模式来强行获得数据。

只读示例退出后停止，不附加运动、音视频采集、后台进程或自启动配置。
交付实际应用目录、语言／SDK 配对、准确的再次运行命令与 shell 前提，以及剩余阻塞。
设备不可用时，说明本地准备已完成，但在线搭建尚未完成。

## 设备 shell 配置与检查

阅读[设备环境指南](../../docs/getting-started/device-environment.zh-CN.md)与
[Aorta／ROS 2 兼容接口](../../docs/interfaces/aorta-ros2.zh-CN.md)。使用指南中的公开 `/opt/vita`
路径；Aorta 是原生入口，ROS 2 是设备本机兼容子集。ROS 路由不可用时，不编造映射或修改 bridge 设置。

- 仅咨询时说明配置，不联系或修改设备。
- 设备配置或在线检查前优先使用 SSH 公钥免密登录。按
  [连接指南](../../docs/robots/quadruped-common/connection.zh-CN.md)复用已有配置，
  尚未配置时先引导用户完成，再从后续实际执行命令的环境使用 `BatchMode=yes` 和仅公钥认证验证。
  不内嵌密码，也不自动回退到密码登录自动化。只读请求不授权安装公钥；保留已有密钥，不向设备传输私钥。
- 使用选定的设备地址或 SSH 别名；不可达或连接被拒绝时停止，提示先连接设备或提供实际 IP。
  认证与主机密钥错误分别说明，不扫描其他目标，也不绕过主机密钥核验。
- 配置设备时，先以 `vbot` 完成 SSH 登录，再在该设备 shell 设置环境；不要在工作站终端执行设备环境配置块。
- 用户要求设备检查时，明确目标连接并使用 `vbot` shell。文件已具备时，在该 shell 运行
  `tools/check_device_environment.py`，否则使用文档中的手动检查。传输独立脚本是单独操作，
  需符合请求范围；检查器自身不会建立连接。
- 用户要求持久化时，保留并备份 `.bashrc`，更新单个标记配置块，检查语法并验证新 SSH 会话。
  不覆盖其他启动内容。
- 非交互工具命令或用户启动脚本在其 Bash 进程中显式加载文档环境，不依赖交互式 `.bashrc` 的继承。
- 仅在用户要求在线检查时，运行指南中有时限的发现／Schema／单条采样命令，每次一条流。
  不通过发布控制消息、调用 service／action、重启服务或修改权限测试环境。

设备检查器不依赖 Python SDK 安装；应用开发按 [Python SDK 指南](../../packages/aorta/python/README.zh-CN.md)
准备配套版本。退出码 0 仅确认 shell 清点；ROS 类型加载、实际收数、
启动持久化与固件兼容性仍需分别检查。超时不表示成功，目录条目不等于实际收到数据。

## 交付结果

总结观测到的工具、缺失要求、发布／SDK 阻塞，以及适用的下一步。
分别说明工作站清点、设备 shell 配置、接口发现、实际收数与持久化证据，仅报告已执行的检查和观测结果。
工作站清点不代表获准连接或修改机器人。
